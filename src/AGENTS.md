# Project Working Instructions

## File changes

- Make requested changes directly in the existing project files.
- Keep changes focused on the user's request and preserve the existing project structure and logic.

## Git workflow

- Leave all file changes uncommitted and unstaged for the user to review and publish manually.
- Do not create or switch branches.
- Do not stage files, create commits, push changes, or create or update pull requests unless the user explicitly requests that exact Git action in the current message.
- Read-only Git commands such as `git status`, `git diff`, and `git log` are allowed for inspection and verification.
